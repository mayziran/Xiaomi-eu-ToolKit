# Xiaomi.eu ToolKit

给 **HyperOS 国际版 / xiaomi.eu** 用户的一个小工具：查看小米推送（MiPush）的**注册情况**，用来排查「为什么某个 App 收不到推送」。

装上就是一个普通 App，另外它同时还是一个 LSPosed 模块 —— **模块功能要等后续版本才会有**，现在即使你在 LSPosed 里启用了它，也不会改变任何东西。

---

## 使用前提

- 手机需要 **root**（Magisk / KernelSU / APatch 都行）
- 系统里有**官方的小米服务框架** `com.xiaomi.xmsf`
- 主要用于 HyperOS / MIUI；其它系统上数据结构可能不一样

**为什么非要 root**：注册记录放在系统应用 `com.xiaomi.xmsf` 的私有目录里，普通 App 读不到。

---

## 三个页面

### 总览

列出和 MiPush 有关的所有应用，每条显示：应用名、包名、注册状态、appId。

- 顶部搜索框可以按 **应用名 / 包名 / appId** 搜
- 下面一排筛选：**全部 / 已注册 / 未注册 / 已注销 / 推送禁用**，每个标签后面是当前数量
- 点任意一条进入详情

> 只包含「和推送有关」的应用，不是把你手机里所有 App 都列一遍。

### 详情

单个应用的详细信息：

| 项目 | 说明 |
| --- | --- |
| appId | 框架分配给这个 App 的编号，有值说明注册表里有它 |
| 注册密钥 | 注册时一起下发的密钥。**有这个才算真正能收到推送** |
| 推送 | 这个 App 的推送有没有被框架禁用 |
| 支持 MiPush | 这个 App 有没有正确集成 MiPush |
| 已安装 / 系统应用 / uid | 基本信息 |

### 诊断

- **官方服务框架**：装的到底是不是官方的小米服务框架（看系统应用身份 + 签名指纹）
- **区域**：`mipush_region` / `mipush_country_code` 的值，以及**框架自己认为推送能不能用**
- **操作**：下面三个按钮
- **统计**：各类数量
- **数据文件**：框架各个数据文件在不在、读不读得到

## 状态说明（最重要的一节）

| 徽章 | 颜色 | 含义 | 该怎么做 |
| --- | --- | --- | --- |
| **已注册** | 绿 | 注册表里有 appId，也有注册密钥，正常 | 无需处理 |
| **已注册·缺密钥** | 黄 | 注册表里有 appId，但**密钥丢了** | 这种多半收不到推送：把这个 App 杀掉重开，或强行停止服务框架后重试，让它重新注册 |
| **未注册** | 红 | 这个 App 集成了 MiPush，但注册表里没有它 | 打开该 App 并保持前台一会儿；或用上一条的办法让它重新注册 |
| **配置不全** | 黄 | 声明了 MiPush 的服务，但不符合规范（exported / 进程设置不对） | 是 App 自身的问题，一般无解 |
| **未集成** | 灰 | 这个 App 本来就不用小米推送 | 正常，忽略即可 |
| **已注销** | 灰 | 框架记录它主动注销过 | 打开该 App 会重新注册 |
| **推送禁用** | 橙 | 已注册，但这个 App 的推送被框架关掉了 | 在系统设置里把该 App 的通知权限打开，或重新启用推送 |

> 「推送禁用」是**单独的一个维度**，可以和「已注册」同时出现。

## 三个操作按钮

诊断页的「操作」卡片，都**需要 root**。

| 按钮 | 做什么 | 注意 |
| --- | --- | --- |
| **一键改为国区（China / CN）** | 往服务框架写 `mipush_region=China`、`mipush_country_code=CN` | 国际版 / xiaomi.eu 装的是国行框架时常用。写完要**重启设备或重启框架**才生效 |
| **强行停止服务框架** | 相当于强制结束 `com.xiaomi.xmsf` 进程 | 安全。框架会被系统重新拉起，注册记录不会丢 |
| **清除数据与缓存** | 清空 `com.xiaomi.xmsf` 的**全部数据**（含注册表） | **危险**：所有 App 的 MiPush 注册都会丢失，需要逐个重新注册，你改过的区域设置也会没了。有二次确认弹窗 |

**除了这三个按钮，这个 App 只读，不会改动你系统里的任何东西。**

## 常见问题

**Q：我搜不到微信 / QQ，是不是有问题？**
A：不是。它们用的是自己的推送通道（或厂商推送联盟），不在这套结构里。总览只列和 MiPush 相关的应用。

**Q：显示「已注册」，但推送还是收不到？**
A：先看**注册密钥**那一行。如果显示「无」，就是「已注册·缺密钥」，属于注册信息不完整。另外也看诊断页的「框架推送」是不是「启用」。

**Q：诊断页里 `mipush_app_info` 显示「不存在」，是坏了吗？**
A：不是。这个文件是**按需创建**的 —— 没有任何 App 被注销或禁用过，它就不会存在。

**Q：「框架推送」显示「禁用（region 不是 China）」是什么意思？**
A：服务框架自己的判断：只有区域是 `China` 时它才认为该推送。国际版如果没把区域设成国区，就会显示禁用。这也正是「一键改为国区」按钮存在的原因。

**Q：改了区域，为什么诊断页还是旧的？**
A：右上角有刷新按钮。区域改动需要重启设备或重启框架才真正生效。

**Q：会破坏保修 / 影响系统更新吗？**
A：这个 App 本身只是读数据。它需要 root，而 root 本身的影响请自行评估。三个操作按钮里只有「清除数据」会真正动到系统数据。

**Q：支持哪些机型？**
A：只要是 HyperOS / MIUI 且有官方 `com.xiaomi.xmsf` 的机型都行。第三方替换版框架（比如 MiPushFramework 那类）的数据结构不一样，可能不准。

## 从源码编译

需要 JDK 21 和 Android SDK（platform 37.2、build-tools 37.0.0）。

```bash
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

也可以在 GitHub 仓库的 **Actions** 页面手动触发 `Build debug APK` 工作流，跑完在 Artifacts 里下载。

## 关于模块

APK 里已经带上了 LSPosed 模块的声明（libxposed API 102，作用域 `com.xiaomi.xmsf`），但入口目前是空的 —— 不装 hook，只打一行日志。以后会在这里加上对框架和第三方 App 的修改能力。

模块声明文件：`app/src/main/resources/META-INF/xposed/`。
